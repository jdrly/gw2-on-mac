# 0.2 has no Cooler job workers

Decided 2026-11-12. Status: accepted. `arm64` only. 0.1.x on `main` keeps the setting, off by
default from its next release (#248).

On 0.1.x GW2's seven job workers take the S cores, and the *Cooler job workers* setting moves some
of them to the P cores to save power. The 0.2 app carried the row over, greyed, with the port to the
arm64 engine planned as the last ticket of step 3, for once 60 holds (#46). I dropped both the row
and the port. macOS moves the game's threads between the core types by itself, on 0.1.x as well, and
I don't want a switch for it on 0.2.

## Consequences

- The row is gone from Settings › Performance, with the `coolworkers` key, its values and reason,
  its checks, its render fixture and its README row.
- `set coolworkers …` is refused as an unknown setting. An old `settings.conf` with a `coolworkers=`
  line loads without an error and loses the line at the next write.
- #46 is closed as not planned. My Wine fork has no QoS switch.
- On 0.1.x the full move, all seven workers, saves 4 to 5 W and costs 3 to 6 FPS at the busy spot,
  so it is off under my never-below-60 rule. In my own 0.1.x install the setting has been off since
  2026-11-04. The 0.1.x app moved three of the seven by default for other players, which no
  session of mine had measured. On 2026-11-17 I turned that default off too (#248), in a pull
  request on `main` with an ADR of its own there. It ships in the next 0.1.x release.

## Alternatives I rejected

- **Keeping the row greyed until the port.** That was its state on 0.2. The port could only save
  watts and cost frames, on an engine that was 12 frames short of 60 in its first session, which is
  why its ticket was last.
