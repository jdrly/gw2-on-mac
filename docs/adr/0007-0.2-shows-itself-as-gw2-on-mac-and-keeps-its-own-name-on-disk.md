# 0.2 shows itself as "GW2 on Mac" and keeps "GW2 on Mac arm64" on disk

Decided 2026-11-12. Status: superseded by ADR 0018 on 2026-11-19 for the name on disk: 0.2 takes
0.1.x's file name and bundle id, and only its folders keep "GW2 on Mac arm64". The shown name stays
as decided here.

The 0.2 app carried "arm64" in its title and described its pieces as "my ntdll and winemac d831f80"
and "DXMT 2483559 · my fork". I wanted version numbers there and the title without "arm64". The name
on disk has a job, though: the bundle id, the app's file name and its folders are "GW2 on Mac arm64"
so 0.2 installs next to 0.1.x and shares nothing with it. So the app has two names. The shown one is
"GW2 on Mac". The one on disk stays.

## Consequences

- "arm64" leaves everything the app shows: the line under the wordmark, window titles, the About
  panel, the menu, alerts, messages and the footer.
- The bundle id, the app's file name and its folders in Application Support, Logs and Caches keep
  "GW2 on Mac arm64". A text that names a folder keeps the folder's real name.
- The code has a shown name and a folder name where it had one (`appName` in `src/native/App.swift`,
  `APP_NAME` in `src/gw2om.sh`, `collect-logs.sh`, `session-report.sh`).
- The Engine check reads `Wine <version> · <commit>` from my build's record, and the Graphics check
  `DXMT <version> · <commit>`. With the engine's own files it shows the engine's title.
- No text a player reads names an issue number or a step of the 0.2 plan.
- An existing install is found at the same paths as before.

## Alternatives I rejected

- **Renaming the folders and the bundle id too.** They keep the name so 0.2 still installs next to
  0.1.x and shares nothing with it.
