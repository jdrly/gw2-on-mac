# 0.2 is the same app as 0.1.x and keeps its own folders

Decided 2026-11-19 by the dispatcher, under my standing rule. Mine to overrule. Status: accepted.
It supersedes ADR 0007's name on disk and the line of ADR 0003 that has 0.2 install next to 0.1.x.
`arm64`, and its third point binds `main` too.

Sparkle 2.10.0 looks for the new app in an update by the installed app's file name, then by its
bundle id, and installs it at the installed app's path (`Autoupdate/SUInstaller.m:81-105`,
`:274-289`). Every 0.2 build so far was `GW2 on Mac arm64.app` with the id
`cz.jandrly.gw2onmac.arm64` (ADR 0007), so no 0.1.x install could take one as its update. Players
would have to find 0.2.0 on the release page, download a second app with the same shown name, and
hear nothing from the 0.1.x they have.

The night of 2026-11-19 settled how 0.1.4 reaches 0.2.0. Four of those decisions are this ADR's:

1. **One app.** 0.2 takes 0.1.x's file name, `GW2 on Mac.app`, its bundle id,
   `cz.jandrly.gw2onmac`, and its feed, `releases/latest/download/appcast.xml`. *Check for
   Updates…* in 0.1.4 then offers 0.2.0 and installs it where 0.1.4 was.
2. **The data folders keep the name `GW2 on Mac arm64`**, in Application Support, Logs and Caches.
   0.2 reads 0.1.x's `GW2 on Mac` folders and never writes them. Taking them over would mix the two
   lines' files: `Caches/…/dxmt/` holds my fork's cache on 0.1.x and the engine's own DXMT's on 0.2.
3. **0.1.5 is the last 0.1.x I plan.** Once 0.2.0 is the latest release, the feed's one item is
   0.2.0. If a bug serious enough for a 0.1.x fix turns up after that, the feed carries two items,
   0.1.x's for macOS 26.0 and 0.2's for 26.4. Sparkle drops every item the Mac's macOS is too old for
   and takes the highest one left (`Sparkle/SUAppcastDriver.m:498-513`), and the appcast isn't
   signed, so I can merge the two by hand.
4. **macOS 26.4 or later, as Mach9 ships.** `LSMinimumSystemVersion` stays 26.4, and the feed's
   item says `sparkle:minimumSystemVersion` 26.4. A 0.1.x install on macOS 26.0 to 26.3 is offered
   nothing and stays on 0.1.x. Nobody I know has run 26.4 yet, and for anyone it fails on, the way
   back is 0.1.x's DMG.

## Consequences

- What ADR 0007 decided for the shown name stays: nothing the app shows says "arm64", a text that
  names a folder gives the folder's real name, and the Engine and Graphics checks read versions.
  The code still has two names. `APP_NAME` is the shown name and now the file name too, and
  `APP_FOLDER` names only the folders (`src/gw2om.sh`, `collect-logs.sh`, `session-report.sh`,
  `appName` and `appFolder` in `App.swift`).
- Every build of `arm64` has the release's identity, a dev build and a release candidate too, as
  dev builds on `main` always had. Installing one replaces whatever `GW2 on Mac.app` is in
  `/Applications`, my 0.1.4 included, so I keep 0.1.4's DMG at hand. A dev build still has no feed
  (ADR 0004).
- The app's preferences live in `cz.jandrly.gw2onmac`, 0.1.x's domain. What I chose in a 0.2 build
  before this, such as the install route and *Quit after launching*, starts again, and what I chose
  in 0.1.x comes along.
- A dev build and the release share `settings.conf`. A dev build turns its rows on once and writes
  them with a `dev_version=` line (ADR 0009). A release build that finds that line reads those rows
  at their defaults, and its next write drops the line, so 0.2.0 over my dev install doesn't run
  with `fex=mine`. A dev build after it turns them on again. A release build already ignored
  `dev-switches.conf`.
- The DMG is `GW2-on-Mac-<version>.dmg` and the deltas `GW2-on-Mac-<version>-from-<old>.delta`, as
  0.1.x's. With 0.1.4's DMG in `release/updates/`, the feed gets a delta from it when Sparkle's
  `generate_appcast` makes one, and `scripts/release.sh` says so when it made none.
- The appcast has one item, for this version only. Sparkle would keep an item for each minimum
  macOS, 0.1.4's too. `scripts/release.sh` stops when the item doesn't name the macOS the engine
  needs, `src/gw2om.sh`'s `MACOS_MIN`. Until #294 it checked the app's `LSMinimumSystemVersion`,
  then the same 26.4.
- 0.1.4 on macOS 26.0 to 26.3 says it is the latest version, because it ignores the reason Sparkle
  gives. #274 has 0.1.5 explain it.
- The update itself is still to be tested on my Mac: a 0.2.0 build with 0.1.x's feed and key,
  served from `127.0.0.1` to a 0.1.4 install (README, Releasing; #270 and #271's UAT).
- Moving a 0.1.x install into 0.2's folders is its own decision, with #272.

## Alternatives I rejected

- **Two apps, as in ADR 0007.** Nothing reaches a 0.1.4 player, and `releases/latest` serves one
  feed, so one of the two apps would have no updates.
- **One app with an engine choice.** It would carry both lines' components, and every feature,
  check and render would exist twice in one build. ADR 0005 already dropped the smaller version of
  that choice.
- **0.2 taking over 0.1.x's folders.** There would be no way back to 0.1.x, and the cache folder
  above would hand one DXMT the other's files.
