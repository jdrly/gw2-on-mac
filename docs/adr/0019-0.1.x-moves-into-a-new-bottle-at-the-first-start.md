# 0.1.x's install moves into a new bottle at the first start

Decided on the night of 2026-11-19 by my dispatcher, under my standing rule, and mine to overrule.
Status: accepted. `arm64` only. These are decisions 3, 5, 9 and 10 of the update plan (GW2 on Mac
workspace `advisor-plans/2026-11-19-update-path/PLAN.md`, its last section).

0.2.0 replaces 0.1.4 through the feed and keeps its own data folder, `GW2 on Mac arm64`. A player
who updates opens an app with no install of its own next to a complete 0.1.x install: Steam with a
remembered login, 70 GB of game, the game's settings, arcdps, ReShade with presets. The import of
#25 brings the game files but not Steam's login, the addons or the app's settings, and it was
written against 0.1.3. Four questions had to be answered before the move could be built.

## Consequences

- **A new bottle with clones (decision 3).** The move makes a new bottle with the arm64 engine,
  and 0.1.x's files are cloned into it: the whole Steam folder over the one Valve's installer just
  made, the profile's `AppData/Local/Steam`, the game's settings folder, and the ReShade folder
  outside the bottle. 0.1.x's bottle is never handed to Mach9's Wine. On the same disk a clone
  costs no space until the two copies drift apart. From another disk the trees are copied after a
  free-space check. ADR 0016's path, Repair over an engine of another release, stays for engine
  moves within the arm64 line.
- **The move starts by itself (decision 5).** The window starts it at the first start when
  `gw2om.sh status` says `move=yes`: this app has no manifest and no bottle, 0.1.x has its
  manifest, a bottle and a complete game, and no move or Start fresh happened here before. While
  0.1.x's Steam, game, ArenaNet installer or Wine runs it waits and says which. The backend refuses
  the move then too, and checks again before each tree it clones and after the last. 0.1.x's
  processes are told as 0.1.x's own `proc_list` tells them: an executable in its folder, the Game
  Mode bundle's copy of the loader included, a winetemp link to its loader, or its stock
  `wineserver`.
- **Only reads (decision 5).** Nothing in 0.1.x's Application Support or Caches folder is opened
  for writing. Both `ReShade.ini` files name this app's folders after the clone, since the
  folder's own ini points `IntermediateCachePath` at 0.1.x's cache. A game folder or a ReShade
  folder that resolves outside this app's folders, a link in 0.1.x's tree, stops the move before
  anything writes through it.
- **Once (decision 5).** A failed or cancelled move removes all it made and leaves this app not
  installed, so the window runs it again at the next start or on *Try again*. A finished move
  writes `moved-from-0.1` (`moved`), and *Start fresh* in Settings › Troubleshooting writes
  `skipped`. Either way the move no longer starts by itself. Uninstall keeps the file, so an
  uninstall doesn't move 0.1.x's install again. *Start fresh* works while nothing is installed,
  so a player whose move waits or failed can still install anew.
- **Addons as they were (decision 9).** arcdps, at `d3d11.dll` or at ReShade's chain path, with
  its settings, and ReShade's three files come with the game folder. The finishing touches put
  them in order as at every Play, and the ReShade folder comes with its presets and the record of
  the compiler 0.1.x placed. #268's UAT is the check that both load under FEX.
- **`crossover` for every bottle (decision 10).** A new bottle's Windows user is `crossover`,
  CrossOver's name for every user. The app passes it as `USER` to every Wine call (`wine_do`,
  `game_env`), and Mach9's Wine names the user after `USER`. The profile folder stays
  `C:\users\crossover`, and Wine's `CryptProtectData` derives the same key as in 0.1.x's bottle,
  so what Steam protected there can be read in the moved one. A bottle an earlier build made keeps
  its user's name, because the app takes the name from the bottle's own `users/` folder. One name
  for every new bottle is one code path, and Collect Logs has no Mac login in the profile's path
  to redact.
- Steam's login across the move is untested (#270). Until that hand test says otherwise, the
  move's summary says Steam may ask for it once, and the first Play after a move shows Steam's
  window.

## Alternatives I rejected

- **Converting 0.1.x's bottle in place.** It leaves no way back: a bottle Wine 11.21 has updated
  isn't one I'd hand to Wine 11.0 again. My rule is a fresh bottle after a major engine change,
  and every 0.2 session I have played ran in a bottle Mach9 made.
- **A move on a click, with Start fresh beside it.** The plan's first draft. I asked for the
  engine update to run by itself with progress, and the move is the same kind of step. A player
  who wants a fresh install finds Start fresh in Troubleshooting.
- **Addons off until the player turns them on.** A player who updates expects the game as it was,
  arcdps and ReShade with it.
- **`crossover` only for moved bottles.** Two code paths and two names to redact, for no gain.
