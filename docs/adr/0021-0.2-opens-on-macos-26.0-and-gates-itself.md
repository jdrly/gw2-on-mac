# 0.2 opens on macOS 26.0 and gates itself

Decided on 2026-11-19 at 15:20, mine. Status: accepted. `arm64` only. It supersedes the
`LSMinimumSystemVersion` half of ADR 0018's fourth point. The plan is in the GW2 on Mac
workspace, `advisor-plans/2026-11-19-os-gate/PLAN.md`.

Amended on 2026-11-20 (#337): `MACOS_MIN` is 26.5, not 26.4, since the engine's loader needs a
function that macOS 26.4.1 lacks (ADR 0018's fourth point). The popup shows on 26.4.x too. The
context below is as of 2026-11-19, when I took the minimum to be 26.4.

Until this decision, 0.2's `Info.plist` asked for macOS 26.4, the minimum I took the engine to
need. On macOS 26.0 to 26.3, macOS refused to open 0.2 with its own alert, which names two
versions and offers no way on. 0.1.x runs there. A player who downloads 0.2.0 from the release
page on such a Mac had nothing to go on but a ticket.

## Decision

- **The app opens on 26.0, as 0.1.x does.** `LSMinimumSystemVersion` is 26.0, and `build.sh`
  takes the deployment target of swiftc and of the two helpers from it, so the three can't
  differ. The engine's minimum is `MACOS_MIN` in `gw2om.sh` and nowhere else.
- **Below `MACOS_MIN` the app shows one popup and does nothing else (#295).** On status's
  `macos_ok=no` the main window shows it at every start. It says why, names the last 0.1.x
  (`LAST_01`), and has Download and Quit. Nothing closes it but Quit. It is #291's Rollback popup
  with another first page, from the same constant.
- **The browser downloads, and I drag.** Download opens `LAST_01`'s DMG in the browser, and the
  popup then lists the steps: quit, open the DMG, drag the app to Applications over this one. 0.1.x
  releases are notarized, so Gatekeeper checks the DMG as it did every 0.1.x download. Sparkle
  can't do it, since its installer refuses a lower version. An installer of my own would need a
  helper that waits for the quit, a way to find a translocated app's real path, a password prompt
  and its own signature checks, all on a macOS I can't test on.
- **The backend writes nothing there.** `gw2om.sh` refuses every command but the ones that only
  read (`status`, `session-status`, `settings`, `scan`, `check-game`, `env`, `rules`) before it
  opens a log, with `preflight`'s sentence. That covers status's own `recover`.
  So neither this app's three folders nor anything of 0.1.x's install is touched, whatever calls
  the script.
- **Sparkle starts after the first status**, and not at all below `MACOS_MIN`. *Check for
  Updates…*, *Settings…* and *Collect Logs…* are disabled there.
- **`release.sh` refuses a release whose `LAST_01` DMG isn't a published asset**, since that link
  is the only way on from the popup.

## Consequences

- Finder no longer marks 0.2 as unusable on macOS 26.3. The popup has to say it, at every start.
- An API newer than macOS 26.0 needs `if #available`. The compiler says where.
- `LSMinimumSystemVersion` no longer says what 0.2 needs. Whatever read it for that purpose reads
  `MACOS_MIN` now. The one reader I found is the feed (#294).
- No runner or Mac I have runs macOS 26.0 to 26.3. The sandbox pretends 26.3 and 26.4.1 with
  `GW2_ON_MAC_MACOS`, and the renders show the popup. That Launch Services opens the bundle there
  and that the drag replaces it is the hand test, #297, after 0.2.0.
- When 0.1.5 ships, `LAST_01` names it, and the popup, Rollback, README and the notes follow.

## Alternatives I rejected

- **The plist at 26.4, as before.** macOS's alert is the ticket this fixes.
- **A popup that can be closed**, with the window's buttons dead behind it. Below `MACOS_MIN` there is
  nothing 0.2 can do.
