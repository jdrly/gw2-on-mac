## GW2 on Mac 0.2.0

GW2 on Mac now runs the game on a Wine built for Apple Silicon, without Rosetta, and moves your
0.1.x install over by itself.

### No more Rosetta
0.1.x ran CrossOver's Wine under Rosetta, so every part of it was Intel code that Rosetta
translated. 0.2.0 runs on athei's Mach9 0.4.0 engine, a Wine built for Apple Silicon. Wine itself,
its Mac driver and my DXMT fork now run as arm64 code. Guild Wars 2 and Steam are still Windows
programs for Intel chips, and FEX translates their code inside Wine. Apple has said that after
macOS 27, Rosetta stays only for some older games, and it hasn't said whether Wine counts. 0.2
doesn't need Rosetta at all.

### A lighter graphics engine
0.2.0 has a newer build of my DXMT fork, the part that turns the game's Direct3D 11 into Metal.
Its encode thread, which writes each frame's Metal commands, needs about half the time it needed
on 0.1.4. In my sessions that was 1.4 to 1.8 ms a frame, against 3.4 ms on 0.1.4. That's CPU time
your Mac no longer spends. It doesn't make crowds faster, since there the game's own main thread
sets the pace.

### Mac fixes from Mach9 0.4.0
Mach9 0.4.0's release notes list these fixes, and my Wine build in 0.2.0 is built on the same Wine:
- Minimizing the game while the Dock is hidden no longer freezes it for 8 seconds.
- The game no longer crashes after it switches to some display modes, such as 1366x768 or
  1680x1050.
- In a display mode shown with black bars, the mouse stays inside the game's picture.
- A game that closes a window no longer hangs with one CPU core at full load.

### Vsync in Settings
Settings › Graphics has a new *Vsync* row under *Frame cap*, on by default. On, my DXMT fork
shows each frame on one of the display's refreshes. Off, it only keeps frames one refresh apart,
or the frame cap's interval. The row does something only while the game's own Vertical Sync is
on. With both on, I set the game's Frame Limiter to Unlimited, and the window suggests the same.
The *Game Mode* row is gone, because the new engine's loader is a Game Mode app by itself.

### arcdps and ReShade
Both switches are in Settings › Interface as on 0.1.4, and the move brings both as they were,
on if they were on, with arcdps's settings and your ReShade presets and shaders. Both are Intel
DLLs, so FEX runs them like the game. I've played with arcdps on this engine. I haven't run
ReShade in the game on it yet.

### Your 0.1.x install moves by itself
At its first start 0.2.0 finds 0.1.x's install and moves it, and the window shows each step. It
makes a new bottle with the new engine and clones 0.1.x's files into it: Steam's folder with your
login and the game, the game's settings, arcdps, ReShade and the ReShade folder. On the same disk a clone takes no extra
space, and the game doesn't download again. From another disk the move copies, after it checks
the free space.
- Your settings come along. *Faster locks* goes back to off, since on 0.2 it is a different
  change with its own default. *Game Mode* and *Cooler job workers* have no row on 0.2.
  *Mouse-look speed* keeps its value, but on 0.2 it scales the mouse's own counts, so the camera
  may turn at another speed. The move's summary names what changed.
- DXMT's shader caches and ReShade's compiled effects stay behind. The game builds them again
  while you play.
- The move waits while 0.1.x's Steam or game runs, and says what it waits for.
- Steam may ask you to sign in once. I haven't tested yet whether its remembered login survives
  the move, so the first Play after it shows Steam's window.
- If you'd rather install anew, *Start fresh* in Settings › Troubleshooting does that.

### 0.1.x stays as it was
The move only reads 0.1.x's folders and never writes them. To go back, download
[0.1.4's DMG](https://github.com/jdrly/gw2-on-mac/releases/tag/v0.1.4) and drag its GW2 on Mac
over this one. It finds its install as it was on the day of the move. What you change on 0.2,
such as graphics settings, key binds or new presets, stays on 0.2, and Steam patches 0.1.x's copy
of the game at its next start. 0.1.4 then offers 0.2.0 again at every check, until you click
*Skip This Version*.

0.1.x's folders stay until you delete them: `GW2 on Mac` in `~/Library/Application Support`,
`~/Library/Caches` and `~/Library/Logs`, the ones without "arm64" in the name. Once they're gone,
so is the way back. On the same disk they share most of their space with 0.2's clones, so deleting
them frees only what the game patched apart since the move.

### macOS 26.4 or later
0.2.0 needs macOS 26.4 or later, because the engine's loader does. On macOS 26.0 to 26.3, 0.1.x
offers no update and keeps working as it is.

### After updating
Open GW2 on Mac. If 0.1.x's Steam or the game still runs, quit them, and the move starts. At the
first Play, sign in to Steam if it asks.
