## GW2 on Mac 0.2.0

GW2 on Mac now runs the game on a Wine built for Apple Silicon, without Rosetta, and moves your
0.1.x install over by itself.

### No more Rosetta
0.1.x ran CrossOver's Wine under Rosetta, so every part of it was Intel code that Rosetta
translated. 0.2.0 runs on athei's Mach9 0.4.0 engine, a Wine built for Apple Silicon. Wine itself,
its Mac driver and my DXMT fork now run as arm64 code. Guild Wars 2 and Steam are still Windows
programs for Intel chips, and FEX translates their code inside Wine. Apple has said that after
macOS 27, Rosetta stays only for some older games, and it hasn't said whether Wine counts. 0.2
doesn't need Rosetta at all.

### A lighter graphics engine
0.2.0 has a newer build of my DXMT fork, the part that turns the game's Direct3D 11 into Metal.
Its encode thread writes each frame's Metal commands. In my two sessions on 0.2.0-dev.23 it took 1.4
and 1.8 ms a frame, about half of the 3.4 ms in my session on 0.1.4. That's no promise of more
frames, because in crowds the game's own main thread usually sets the pace.

### Mac fixes from Mach9 0.4.0
Mach9 0.4.0's release notes list these fixes for games on the Mac, and my Wine build in 0.2.0 is
built on that same Wine. I haven't seen any of these problems in Guild Wars 2 myself.
- Minimizing a game while the Dock is hidden no longer freezes it for 8 seconds.
- A game no longer crashes after it switches to some display modes, such as 1366x768 or
  1680x1050.
- In a display mode shown with black bars, the mouse stays inside the game's picture.
- A game that closes a window no longer hangs with one CPU core at full load.

### Vsync in Settings
Settings › Graphics has a new *Vsync* row under *Frame cap*, on by default. On, my DXMT fork
shows each frame on one of the display's refreshes. Off, it asks Metal only for a minimum time
between frames, one refresh or the frame cap's interval. The row does something only while the
game's own Vertical Sync is on. With both on, I set the game's Frame Limiter to Unlimited, and the
window suggests the same. The *Game Mode* row is gone, because the new engine's loader is a Game
Mode app by itself.

### arcdps and ReShade
Both switches are in Settings › Interface as on 0.1.4, and the move brings both as they were,
on if they were on, with arcdps's settings and your ReShade presets and shaders. Both are Intel
DLLs, so FEX runs them like the game. I've played on this engine with ReShade and arcdps on
together.

### Your 0.1.x install moves by itself
At its first start 0.2.0 finds 0.1.x's install and moves it, and the window shows each step. It
makes a new bottle with the new engine and moves the game into it: Steam's folder with your login
and the game, or on ArenaNet's route the game's folder. That's a rename on the same disk, which is
instant, so the update never needs room for a second copy of the game, and the game doesn't
download again. The game's settings, arcdps, ReShade and the ReShade folder come along too.
- Your settings come along. *Faster locks* goes back to off, since on 0.2 it is a different
  change with its own default. *Game Mode* and *Cooler job workers* have no row on 0.2.
  *Mouse-look speed* keeps its value, but on 0.2 it scales the mouse's own counts, so the camera
  may turn at another speed. The move's summary names what changed.
- DXMT's shader caches and ReShade's compiled effects stay behind. The game builds them again
  while you play.
- The move waits while 0.1.x's Steam or game runs, and says what it waits for.
- If 0.1.x's game is on another disk than 0.2's folder, the move stops before it changes anything
  and says why. It never copies the game.
- If the move fails, or you cancel it, or GW2 on Mac is killed in the middle, the game goes back to
  0.1.x's folder.
- On the first start after the move, Steam may show "steamwebhelper is not responding". Try
  *Restart Steam with GPU Acceleration disabled*. In my test on 0.2.0-rc.3 that got past it, and
  Steam started logged in. If Steam asks you to sign in, sign in once. The first Play after the
  move shows Steam's window. I'm tracking it in [#264](https://github.com/jdrly/gw2-on-mac/issues/264).
- If you'd rather install anew, *Start fresh* in Settings › Troubleshooting gives the game back to
  0.1.x first, then shows the install choices.
- If a 0.2 test build is installed, 0.2.0 keeps that install and moves nothing. A game in a Steam
  library outside 0.1.x's bottle doesn't move either. *Game files I already have* can still bring
  it over, with *Choose folder…* for that library.

### Going back to 0.1.4
After the move the game lives in 0.2, so 0.1.x has none. *Rollback to 0.1.4* in Settings ›
Troubleshooting gives it back: it renames the game to where 0.1.x had it, with the addon files
0.1.x had, and then offers 0.1.4's DMG. Quit GW2 on Mac and drag 0.1.4 to Applications over it.
0.1.4 finds its install as it was on the day of the move, with the game as 0.2 left it, patches
included. What you changed in the game's settings on 0.2, such as graphics settings, key binds or
new presets, stays on 0.2. 0.1.4's automatic checks then offer 0.2.0 again, until you click *Skip
This Version*. If you update again, 0.2's window offers *Move it in again*.

Uninstall in 0.2 refuses while the moved game is in its bottle, since that is the only copy. Use
*Rollback* first.

0.1.x's folders stay until you delete them: `GW2 on Mac` in `~/Library/Application Support`,
`~/Library/Caches` and `~/Library/Logs`, the ones without "arm64" in the name. Once they're gone,
so is the way back. After the move the game isn't in them, so they hold 0.1.x's engine, the rest
of its bottle and its caches.

### macOS 26.4 or later
0.2.0 needs macOS 26.4 or later, because the engine's loader does. On macOS 26.0 to 26.3, 0.1.x
offers no update and keeps working as it is. Take
[GW2 on Mac 0.1.4](https://github.com/jdrly/gw2-on-mac/releases/tag/v0.1.4) there. If you open
0.2.0 on such a Mac, it changes nothing and shows one window that downloads 0.1.4's DMG. Drag that
app to Applications over 0.2.0.

### After updating
Open GW2 on Mac. If 0.1.x's Steam or the game still runs, quit them, and the move starts. At the
first Play, sign in to Steam if it asks.
