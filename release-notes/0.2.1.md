## GW2 on Mac 0.2.1

This fixes 0.2.0's crash at start on macOS 26.

### The crash on macOS 26
On macOS 26, 0.2.0 closed Guild Wars 2 a few seconds after Play, before the game's launcher
appeared. It happened on an M1 and an M2 Max. The cause was in KosmicKrisp, the engine's Vulkan
driver. It asked Metal whether a buffer was sparse, through a call Apple's SDK lists from macOS
26.0. On those Macs the call throws, although Metal answers that buffers have it. On my M5 with
macOS 27 the call works, so 0.2.0 ran there.

0.2.1 ships KosmicKrisp from my own Mesa fork, which knows which buffers it made sparse and never
asks Metal ([#339](https://github.com/jdrly/gw2-on-mac/issues/339)). On the M1 with macOS 26.7.3,
where 0.2.0 crashed every time, the game now starts.

### After updating
If Steam is still running from 0.2.0, Play asks you to quit it, since the fixed driver can only go
in while Steam is closed. Quit Steam, then click Play again.

### Also in 0.2.1
- 0.2 needs macOS 26.5 or later. On 26.4.1 the engine couldn't start, because it uses a function
  that version lacks. On macOS 26.0 to 26.4.x the app opens a window that offers 0.1.4, the
  last 0.1.x, which runs there.
- The ArenaNet route's download link goes to `account.arena.net/welcome`. The old link returned
  "page not found".
- When a first install fails, it now also removes the `dxmt.conf` and the game's rules it made.
- *Collect Logs* picks macOS's `.ips` crash reports of Wine, Steam and the game by the app they
  belong to, not by file name. It removes home folder paths from them, as from the other logs.
