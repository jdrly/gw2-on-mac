## GW2 on Mac 0.2.1

This fixes 0.2.0's crash at start on macOS 26.

### The crash on macOS 26
On macOS 26, 0.2.0 closed Guild Wars 2 a few seconds after Play, before the game's launcher
appeared. The cause was in KosmicKrisp, the engine's Vulkan driver. It asked Metal whether a buffer
was sparse, through a call Apple's SDK lists from macOS 26.0. On macOS 26 that call is only a stub
that throws, even though Metal says buffers support it. On macOS 27 the call works, which is why
0.2.0 ran there.

0.2.1 ships KosmicKrisp from my own Mesa fork. It knows which buffers it made sparse and never asks
Metal. On an M1 with macOS 26.7.3, where 0.2.0 crashed every time, the game now starts
([#339](https://github.com/jdrly/gw2-on-mac/issues/339)).

### If Steam is still open
If Steam is still running from 0.2.0 when you update, Play asks you to quit Steam first. The fixed
driver can only go in while Steam is closed.

### Also in 0.2.1
- 0.2 needs macOS 26.5 or later. On 26.4.1 the engine couldn't start, because it uses a function
  that version lacks. Below 26.5 the app shows the same window as below 26.4 did, with the
  download of 0.1.4.
- The ArenaNet route's download link goes to `account.arena.net/welcome`. The old link returned
  "page not found".
- A failed first install now removes everything it made, `dxmt.conf` and the game's rules
  included.
- *Collect Logs* now finds macOS's crash reports of Wine, Steam and the game by the app they
  belong to, not by file name. Home folder paths in them are removed, as in the other logs.
