## GW2 on Mac 0.2.1

The game no longer crashes at start on Macs whose Metal driver lacks a method that macOS 26 added.

### No more crash at start on some Macs
On an M2 Max with macOS 26.5.2, 0.2.0's game ended seconds after it started, with
`-[AGXG14XFamilyBuffer sparseBufferTier]: unrecognized selector` in `wine.log`. macOS 26 added
`sparseBufferTier` to every Metal buffer, and Metal may ask any buffer for it, but that Mac's
graphics driver doesn't answer it. My DXMT fork now adds the answer where the driver lacks it: "not
sparse", which is true for every buffer DXMT makes. Macs whose driver already answers don't
change. The fix is in my DXMT fork, `37c0037`
([jdrly/dxmt#341](https://github.com/jdrly/dxmt/issues/341)).

### Collect Logs takes the game's crash reports
When the game or Steam crashes, macOS writes its own crash report, with the full stack. *Collect
Logs* now puts macOS's reports of the game, Steam and Wine from the last 7 days into the zip, the
newest 10, with your home folder and user name taken out like in the other files. It used to pick
them by file name only, and the zip from that M2 had no report of the game.
